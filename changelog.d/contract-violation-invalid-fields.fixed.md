- **A required field that arrived in the wrong shape was reported as missing (#196).** A backend that sent a string for a `quantity`/`money` field produced `contract violation … missing required field(s): pricePerNight`, which sent the reader looking for a field that was there. The violation now keeps the two apart, in the text and in `_meta["dev.archstone/contract_violation"]`: `missing` lists only fields the provider did not send, and a new `invalid` lists fields it sent in the wrong shape as `{ field, expected }`, where `expected` is the declared type. `invalid` is present only when non-empty, so a violation with nothing malformed is byte-identical to before; `missing` keeps its key and shape, but a malformed field is no longer in it. An optional field in the wrong shape is likewise named in a separate degraded note and in `invalid` (it also stays in `degraded`, which still lists every optional field left out of the result). `ExecuteResult` and `ContractRecording` carry the same `invalid`. The provider's value is never echoed.
