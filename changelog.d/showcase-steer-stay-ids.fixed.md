- **Models passed a stay's name where the showcase expects its id.** Against the hosted demo a model called `wanderlust_stay-photos` with `{"stayId":"Casa Alfama"}` and got a bare 404, or asked the user for a city instead of searching by name. Every stay-id input in the showcase manifest now says it is the `id` field returned by `wanderlust_search` (like `ws-1001`), never a name, and that a stay the user names is found by calling `wanderlust_search` with that name as `destination`; the `destination` description says a stay's own name works. Declared descriptions only: the runtime and the ids are unchanged.
